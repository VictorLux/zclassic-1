## Why this matters

Today the binary is reproducible only if a builder happens to have the
same gcc version, same glibc, same OS — which is a high bar that
doesn't actually hold across builder machines. `flake.nix` pins
EVERYTHING (compiler, libc, every transitive dep, every vendored lib
fetched at locked SHA) in a single declarative file.

After this PR ships:
- `nix build .#zclassic23` produces a binary on any machine with Nix
  installed.
- `nix develop` drops the user into the exact build environment.
- The user (or anyone) can verify the binary's identity by running the
  build on a different machine and comparing `sha256sum`.

This is foundational for Phase 5d (cosign signing of releases): there's
no point signing a binary nobody else can reproduce. The Personal
Sovereignty Stack vision requires that **the user can verify the
binary is what they think it is** — without trusting our build farm.

This PR ships the SKELETON. Byte-identical reproducibility across
machines is a separate gate (Phase 5c `make verify-reproducibility`).
The skeleton's bar is just "it builds successfully via `nix build`."

## What flake.nix needs to do

1. Declare inputs: pinned `nixpkgs` (commit SHA, not a moving tag).
2. Declare outputs:
   - `packages.<system>.zclassic23` — the binary derivation.
   - `packages.<system>.test_zcl` — the test binary derivation (same
     source, different make target).
   - `devShells.<system>.default` — shell with all build tooling for
     interactive dev.
   - `apps.<system>.zclassic23` — runnable app (`nix run`).
3. Build by invoking the existing `make -j$NIX_BUILD_CORES`.
4. Install the artifacts to `$out/bin/`.

## Files to create

### `flake.nix` (~60 lines)

```nix
{
  description = "ZClassic23 — single-binary personal sovereignty stack";

  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/<PIN_TO_SPECIFIC_COMMIT>";
    flake-utils.url = "github:numtide/flake-utils";
  };

  outputs = { self, nixpkgs, flake-utils }:
    flake-utils.lib.eachDefaultSystem (system:
      let
        pkgs = import nixpkgs { inherit system; };
        zclassic23-pkg = import ./nix/zclassic23.nix { inherit pkgs; };
      in {
        packages = {
          default      = zclassic23-pkg;
          zclassic23   = zclassic23-pkg;
        };

        devShells.default = pkgs.mkShell {
          inputsFrom = [ zclassic23-pkg ];
          packages = with pkgs; [
            gdb valgrind clang-tools
          ];
        };

        apps.zclassic23 = {
          type = "app";
          program = "${zclassic23-pkg}/bin/zclassic23";
        };
      });
}
```

For the nixpkgs commit pin: pick a recent NixOS-stable commit from
`https://github.com/NixOS/nixpkgs/commits/release-25.05` (or whatever
the current stable branch is). Document the choice in
`docs/REPRODUCIBLE_BUILDS.md` so future updates have context.

### `nix/zclassic23.nix` (~50 lines)

```nix
{ pkgs }:

pkgs.stdenv.mkDerivation {
  pname = "zclassic23";
  version = "0.0.0-dev";   # bumped at release time

  src = builtins.path {
    path = ../.;
    name = "zclassic23-source";
    # Filter out build artifacts + non-source files.
    filter = path: type:
      let basename = baseNameOf path;
      in !(builtins.elem basename [
        "result" "result-bin"
        ".git" ".direnv"
        "test_zcl" "zclassic23" "zclassic-cli"
        "node.db" "node.log" "data"
      ]) && !pkgs.lib.hasSuffix ".o" path;
  };

  nativeBuildInputs = with pkgs; [
    gcc14            # match the C23 requirement
    gnumake
    pkg-config
    python3          # for any build-time scripts
  ];

  buildInputs = with pkgs; [
    openssl
    libevent
    sqlite
    # add others as `make` fails to find them
  ];

  # SOURCE_DATE_EPOCH and other reproducibility env vars are set
  # automatically by Nix.

  buildPhase = ''
    runHook preBuild
    make -j$NIX_BUILD_CORES
    runHook postBuild
  '';

  installPhase = ''
    runHook preInstall
    mkdir -p $out/bin
    cp zclassic23 zclassic-cli test_zcl $out/bin/ || true
    runHook postInstall
  '';

  doCheck = false;   # tests run separately via `nix flake check`

  meta = with pkgs.lib; {
    description = "ZClassic23 personal sovereignty stack";
    license = licenses.asl20;   # Apache-2.0
    platforms = platforms.linux;
  };
}
```

### `docs/REPRODUCIBLE_BUILDS.md` (~80 lines)

Sections:
1. Why reproducibility matters (1 paragraph).
2. `nix build .#zclassic23` recipe.
3. How to verify byte-identical build (run on a different machine,
   compare `sha256sum result/bin/zclassic23`).
4. Updating the nixpkgs pin (`nix flake update`, then run a build to
   make sure everything still compiles, commit `flake.lock`).
5. Known non-reproducibility sources to watch:
   - `__DATE__` / `__TIME__` C macros — Nix sets `SOURCE_DATE_EPOCH`
     but they may still leak.
   - Embedded build paths — Nix uses `/nix/store/<hash>-...` which is
     deterministic per source SHA.
   - Linker order non-determinism — usually OK with modern GCC, but
     `-Wl,--sort-section=name` is the escape hatch.
6. Future: Phase 5d cosign signing of release binaries.

## What this does NOT do

- Does NOT replace the existing `make` build. `make -j$(nproc)` still
  works as today; Nix wraps it.
- Does NOT add Nix as a hard dependency for developers. The Makefile
  build stays first-class.
- Does NOT wire CI to use Nix (that's 5b-2).
- Does NOT achieve byte-identical reproducibility across machines
  (that's 5c — a separate gate with its own escape hatches).
- Does NOT sign anything (that's 5d).

This PR is the foundation. The follow-ups stack cleanly on top.
